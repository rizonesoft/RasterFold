## adversarial

1. **P1: Adam7 decoding writes beyond its allocation.** `src/png.c:88` allocates `(w * channels + 1) * h + 7`, but `src/png.c:100` includes filter bytes for every pass row and passes that larger bound to inflate at `src/png.c:102`. For a valid 32×32 RGB Adam7 image, the allocation is **3,111 bytes** while inflate writes **3,132 bytes**. Larger heights increase the overwrite. Compute the exact pass size before allocating.

2. **P1: Huffman validation accepts oversubscribed and incomplete trees.** `src/zlib.c:64` compares the number of symbols with `2^length`, ignoring the code space consumed by shorter codes. For example, one length-1 code plus three length-2 codes passes despite exceeding the available code space. Length 15 is never checked, and incomplete trees are accepted without distinguishing the permitted single-symbol cases. Malformed streams can consequently decode successfully instead of returning exit 4. Validate remaining code space at every depth and apply alphabet-specific completeness rules.

## integration

3. **P1: Valid narrow Adam7 images are rejected.** `src/png.c:100` counts filter bytes when `pw == 0`, and `src/png.c:112` processes those nonexistent rows. A valid interlaced 1×1 RGB image contains four inflated bytes; this implementation requires seven and rejects it. Skip passes with either dimension zero in both loops. [PNG filtering requirements](https://www.w3.org/TR/2003/REC-PNG-20031110/#9Filters) explicitly exclude filter bytes from empty passes.

## source-defect

4. **P1: Unknown critical PNG chunks are silently discarded.** The chunk dispatch falls through at `src/png.c:81` for every unrecognized type. Inserting a CRC-valid `ABCD` chunk into an otherwise valid image still permits conversion, although that chunk can change how its pixels must be interpreted. Unknown critical chunks must stop extraction; only unknown ancillary chunks may be ignored. [PNG decoder requirements](https://www.w3.org/TR/2003/REC-PNG-20031110/#13Decoders).

5. **P1: Invalid PNG structure is accepted.** `src/png.c:65` permits IDAT chunks separated by another chunk, while `src/png.c:77` accepts a nonempty IEND and stops without checking remaining input. CRC-valid malformed files can therefore produce output instead of exit 4. Track the IDAT sequence, require zero-length IEND, and enforce the agreed trailing-data policy. [PNG chunk ordering and layout](https://www.w3.org/TR/2003/REC-PNG-20031110/#5DataRep).

6. **P1: Invalid zlib headers bypass validation.** `src/zlib.c:134` checks CM, FCHECK and FDICT but omits CINFO. Changing a valid stream’s CMF to `0x88` and recomputing FCHECK leaves the payload and Adler checksum usable, so it is accepted despite declaring a forbidden window size. Reject CINFO above seven as required by [RFC 1950](https://www.rfc-editor.org/rfc/rfc1950).

## optimization

Bounded blocks and a window-sized match history avoid this deterministic failure.
