## adversarial: needs-attention

1. P1 **Failed staging attempts can delete existing files.** `converter/src/compare.c:963` unlinks `active_path` when submission fails, including refusal because that path already exists. The predictable temporary name does not establish ownership, and `converter/src/output.c:2393` deletes whichever regular file occupies it. Preserve colliding files and clean up only artifacts demonstrably owned by this attempt.

2. P1 **Concurrent history appends can silently lose successful entries.** `converter/src/report.c:1725` reads history without serializing the subsequent replacement. Two appenders can read the same prefix, both pass the size check at `converter/src/output.c:2236`, then both successfully replace it at `converter/src/output.c:2309`. The second replacement discards the first appended entry while retaining a valid hash chain. Windows has the equivalent unconditional replacement at `converter/src/output.c:2202`. Serialize the entire read/validate/append transaction across writers.

3. P1 **Windows cleanup drops its directory protection before deleting.** `converter/src/output.c:2347` closes the ancestor handles before identity lookup and `DeleteFileW` at `converter/src/output.c:2363`. Replacing an ancestor with a junction in that interval redirects deletion to another directory; checking the final file's reparse attribute does not detect a junction ancestor. The hash and history readers similarly release their anchors before opening at `converter/src/output.c:1793` and `converter/src/output.c:1929`.

4. P1 **A malformed read-back count causes an out-of-bounds stack read.** `converter/src/metrics.c:279` accepts the callback's `got` without checking it against `sizeof(chunk)`. If `bytes_written` exceeds 64 KiB, a callback returning 65,537 can reach `rfc_sha256_update` at `converter/src/metrics.c:293` with a length exceeding the buffer. Apply the existing reader bound check used at `converter/src/input.c:1682`.

5. P1 **Report validation accepts unterminated fixed-size strings.** `converter/src/report.c:310` checks only the first byte of provenance fields, while formatting uses unbounded string traversal at `converter/src/report.c:607`. Other public arrays, including candidate `detail`, receive no termination check before serialization at `converter/src/report.c:866`. A fully occupied, unterminated final candidate detail can read beyond the report allocation. Validate termination within every array's capacity before comparing or formatting it.

## integration: needs-attention

6. P1 **A nonzero setting count with a null settings pointer crashes.** Candidate validation at `converter/src/compare.c:534` checks only the count's upper bound. An otherwise valid supported candidate with `setting_count = 1` and `settings = NULL` is dereferenced at `converter/src/compare.c:807`. Reject this combination before accessing settings.

7. P1 **Repeated iterations transfer ownership of the same callback context repeatedly.** `converter/src/compare.c:950` copies `stage_ops`, including `destroy_user_ctx`, into every independently submitted job. Each submission creates its own owning context box at `converter/src/scheduler.c:1616`; releasing it invokes the destructor at `converter/src/job_internal.h:304`. With multiple iterations, later callbacks can access freed state and subsequent releases can double-free it. Retain one comparison-owned context across iterations.

8. P2 **A successful append can make history unreadable by its own reader.** The reader enforces a 64 MiB ceiling at `converter/src/output.c:1903`, but `converter/src/report.c:1764` does not check the combined existing and appended length. An append crossing that boundary returns success, after which reads and further appends return `RFC_ERR_LIMIT_EXCEEDED`. Reject before replacement or implement a compatible storage policy.
