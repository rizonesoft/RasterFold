### adversarial: needs-attention

1. P1 **Opaque properties bypass the memory reservation.** `converter/codecs/avif.c:444` bounds ICC properties and checks `mdcv` length, but accepts arbitrary-sized unknown properties without counting their payloads. The bundled parser copies those payloads at `tools/converter-src/libavif/src/read.c:2975`, including unassociated properties. Meanwhile, `converter/codecs/avif.c:1231` reserves approximately 15 MiB plus estimated EXIF/XMP. A small image containing a large opaque property can therefore allocate far beyond its reservation before header validation. Bound and account for all parser-owned property allocations before calling libavif, with a hostile-property regression fixture.

2. P1 **Preflight permits quadratic work that cancellation cannot interrupt.** Every EXIF/XMP item at `converter/codecs/avif.c:704` rescans the entire reference table through `converter/codecs/avif.c:349`. Items attached elsewhere skip the duplicate checks at `converter/codecs/avif.c:712`, so thousands of unrelated metadata items and references remain admissible. For example, 60,000 items and references cause approximately 3.6 billion box visits before libavif is called. Neither loop checks cancellation. Use bounded reference processing and cancellation checks, and test this construction.
