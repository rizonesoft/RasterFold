## Lessons

- Keep the working tree invariant while `check-all.py` or `review-dispatch.py` runs by buffering cron heartbeat timestamps in memory and flushing afterward, so `tests/test_docs.py` and candidate commit checks never observe mid-run edits.
- Avoid invoking `scripts/campaign_guard.py heartbeat-still` while `drift-check.py` or `check-all.py` is running: atomic replacement of `build/claude-campaign-state.json` changes `build/` directory `st_mtime_ns` mid-snapshot and triggers `--write-site-receipt` check-mode read-only failures. Use read-only `whoami`/`hook-error`/`pending-cancel` during `check-all.py` and run `heartbeat-still` immediately after the suite finishes and commits.
- Avoid live Windows loopback `\\127.0.0.1` SMB probes in tests and shells on hosts where TCP 445 hangs; use an explicit `CreateFileW`-boundary test mapping seam (`rfc_output_set_win32_unc_root_for_testing`) and `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` job objects on Windows child helpers instead.
- When WSL squashfs snaps detach (`/snap/gh/751`: `Transport endpoint is not connected`), use Windows `"/mnt/c/Program Files/GitHub CLI/gh.exe"` with `tr -d '\r'` as a scoped `git -c` credential helper override and filter `/snap` from `PATH` with `< /dev/null` when invoking `scripts/ci_status.py`.
