# The unattended run

One double-click finishes RasterFold to 100%: every open TODO section shipped, reviewed, and stamped, the terminal release acceptance re-run, and the plan closed. This file is the contract the launcher and the run both follow.

## How it starts

The Windows Desktop shortcut `RasterFold Unattended Run.lnk` opens Windows Terminal into this WSL checkout and runs `scripts/unattended-run.sh`, which:

1. Runs `python3 scripts/unattended-preflight.py`. Any FAIL stops the launch with the reason on screen (the terminal stays open). Nothing starts against a dirty tree, a stale plan, a missing reviewer, or a low disk.
2. Starts Muse straight on `main` (never a branch, never a worktree) with `--yolo --disable-request-user-input --model muse-wonder-1.0 --reasoning-effort medium` and the Spark/Ember agent definitions in `.agents/muse-agents.json`, seeded with the prompt below. The unattended lead is Muse Wonder, not Wonder Full (operator directive 2026-11-10): the campaign is paving the way for Wonder and then Spark to run it, so every mechanic the run depends on (sections, specs, run files, gate commands) is written to be followed cold by the weakest tier that will ever read it, with exact commands and exact acceptance checks and no assumed context.

## The seed prompt (verbatim in unattended-run.sh)

> Act with full autonomy (operator directive 2026-11-10): decide and act, self-heal every defect and red gate at its owning layer, improve the tooling, runners, and plan as you go filing what you discover through add-todo, and hold the best-in-class bar against anyone; never stop at impossible without measured proof recorded in a section. Unattended RasterFold campaign. First create the session goal: "Finish RasterFold 100% complete and excellent: every open TODO section built, gated, reviewed through the pinned three-pass schedule, stamped, and committed straight on main; then the terminal release acceptance passes and the plan closes. Best lossless RGB codec in its class on the research corpus, with no placeholders." Then load the process-plan skill and run it end to end: audit, start the campaign guard and the in-session heartbeat (muse.cron_create, 3-59/5 * * * *, canonical prompt from the skill), and ship section after section through process-todo-section plus review-todo-section until query ready prints 0 runnable now. Never ask the operator a question: where a section leaves a choice open, take the industry-standard option, record the decision and its reversal cost in the section, and carry on. Delegate by tier, cheapest capable first: deterministic work to scripts, verbatim literal work to rf-ember-literal, read-only lookups and exact-spec edits to rf-spark-scout and rf-spark-hands, and most section implementation under your written spec to rf-wonder-hands; honor their ESCALATE-SPARK, ESCALATE-WONDER, and ESCALATE-LEAD replies by re-delegating one tier up, verify every line a subagent produces before it lands, and keep planning, format decisions, gate verdicts, stamps, and commits on yourself as lead. A commit is not a stop. A red gate is repaired at its owning layer, never bypassed. Default every task to the lowest tier that can pass its checkpoint, verify with the cheapest falsifier (script exit codes, then deterministic equivalence, then your reading), allow one repair attempt per failure cause per tier before escalating, promote a work class one tier permanently after two verification failures, and record delegation counts by tier in the run file. Milestone gates are capped (D99 T01 §8): at most 13 follow-up experiment rounds per gate; at the cap close the gate accepted-missed with the figures recorded and the target text unchanged, file its one dormant backlog revisit entry (D99 T01 §8 triggers: stronger model pinned, incidental re-measurement crossing the bar, new format version, new technique), never park a gate open waiting, then move on. Stop only at plan closeout, a recorded park where every leftover row is blocked or runnable-elsewhere, or an escalation the tree cannot fix.

## Why it actually runs unattended

- `--yolo` disables approval and the sandbox for the run and trusts the workspace, so no tool call waits on a human. `--disable-request-user-input` withholds the question tool entirely: the run cannot park on a question. The AGENTS.md autonomy rule (operator directive 2026-11-10) covers the rest: decide and act, self-heal at the owning layer, improve tooling and plan as it goes, hold the best-in-class bar, and treat "impossible" as a claim needing measured proof in a section record.
- The run guard is the campaign guard plus the in-session cron heartbeat from `process-plan`: a stalled or crashed turn is resumed inside the same session with full context, and six resumptions with no tree change trip the stall breaker instead of burning tokens forever. Muse has no Stop hook; the guard file plus heartbeat carry it, exactly as the skill maps.
- Reviews never wait on the operator: `scripts/review-dispatch.py` runs the pinned reviewer (muse routes to Astra via the Codex CLI) through plan, adversarial round, completion, and reconciliations up to the 33-pass cap per section.
- Every commit passes the local hooks (staged-tree TODO validate, plan audit, drift) with no `--no-verify`, straight on `main`, one section per logical candidate range.

## The tier ladder, without losing quality

Work goes to the cheapest tier that can do it without quality loss and escalates one tier at a time (operator directive 2026-11-10). `.agents/muse-agents.json` defines the model tiers, loaded by the launcher through `--agents`:

| Tier | Agent / model | Work it takes |
| --- | --- | --- |
| 0 | Scripts (no model) | Anything a tracked script or one deterministic command does exactly: builds, measurements, plan sync, generated files. A recurring mechanical step gets scripted once, never delegated twice |
| 1 | `rf-ember-literal` (muse-ember-1.0) | Verbatim replacement, one exact command returned verbatim, list reshaping. Replies `ESCALATE-SPARK` on anything non-literal |
| 2 | `rf-spark-scout` and `rf-spark-hands` (muse-spark-1.3) | Read-only searches, counts, inventories, claim re-measurement, one named gate quoted verbatim; an exact lead-written edit spec outside codec logic. Reply `ESCALATE-WONDER` on any decision or mismatch |
| 3 | `rf-wonder-hands` (muse-wonder-1.0) | Most section implementation under a lead-written spec: multi-file edits, debugging from evidence, drafting sections and tests. Replies `ESCALATE-LEAD` on format decisions, gate verdicts, conflicting evidence, irreversibles, stamps, commits |
| Lead | muse-wonder-1.0 (the writer; attended sessions may run muse-wonder-full-1.0) | Planning, hardest diagnosis, format decisions, gate verdicts, full-diff review of every delegated change, stamps, commits |

Escalation is a reply token carrying the evidence and the specific question; the delegating session re-delegates one tier up, and no tier improvises past its boundary to avoid escalating. The quality rule is the lead's, not the subagent's: the lead reads every delegated diff in full and independently re-runs or spot-checks every fact a decision rests on, exactly as `.agents/skills` already require of cheaper implementers. Before a new class of work is delegated at a tier, the lead replays it once on a known-answer input; a mismatch keeps that class one tier up.

### Where the savings come from, and what guarantees the quality

The aim is the most usage saved at the quality of a Wonder-Full-only run. That works only because shipped quality in this repo is decided by an author-independent pipeline (section checkpoints with named commands, the gates, the pinned three-pass independent review, the stamp), not by which model typed the diff. Delegation changes who produces the candidate; it never changes what the candidate must pass. The savings then come from moving production down (generation and its iterate-until-green loops are the expensive part) while keeping verification as cheap as it can be without weakening it, in a fixed order: script gates first (exit codes cost no model usage; the worker runs them, the lead reruns the named checkpoint and reads summary lines), then deterministic equivalence (diff scope against the spec's file list, regenerate-and-diff, oracle and known-answer byte identity), and model reading only for semantics no script can falsify (the lead's single full-diff read of Wonder-tier work). Three disciplines keep cheap tiers from burning the savings back: routing defaults down (the lead keeps only work no lower tier can do under a verifiable spec, and writes that spec first), one repair attempt per failure cause per tier then escalation, and permanent one-tier promotion of any work class that fails lead verification twice. Honest limit: equivalence holds for everything the pipeline can falsify, which is most of this repo; for open-ended judgment it cannot, which is why format decisions, gate verdicts, and bar changes never enter the ladder. Default reasoning efforts follow the tiers (Ember and Spark low, Wonder medium, the launcher pins the lead medium), and a campaign's run file records delegation counts by tier so savings stay visible against `muse usage` instead of assumed.

## Stopping and resuming

- Operator stop in words: `python3 scripts/campaign_guard.py end --reason operator-stop`, delete the heartbeat job, done (process-plan spells the order).
- Resume: double-click the shortcut again. Preflight refuses while a guard from a live run exists; a dead run's guard is taken over only through `acquire --handover <reason>` as the skill requires, never by deleting files.
