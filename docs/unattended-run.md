# The unattended run

One double-click finishes RasterFold to 100%: every open TODO section shipped, reviewed, and stamped, the terminal release acceptance re-run, and the plan closed. This file is the contract the launcher and the run both follow.

## How it starts

The Windows Desktop shortcut `RasterFold Unattended Run.lnk` opens Windows Terminal into this WSL checkout and runs `scripts/unattended-run.sh`, which:

1. Runs `python3 scripts/unattended-preflight.py`. Any FAIL stops the launch with the reason on screen (the terminal stays open). Nothing starts against a dirty tree, a stale plan, a missing reviewer, or a low disk.
2. Starts Muse straight on `main` (never a branch, never a worktree) with `--yolo --disable-request-user-input --model muse-wonder-1.0 --reasoning-effort medium` seeded with the prompt below. No worker subagents are loaded: the tier roster was removed by operator directive 2026-11-10, and the run is lead-only. The unattended lead is Muse Wonder, not Wonder Full (operator directive 2026-11-10): the campaign is paving the way for Wonder and then Spark to run it, so every mechanic the run depends on (sections, specs, run files, gate commands) is written to be followed cold by the weakest tier that will ever read it, with exact commands and exact acceptance checks and no assumed context.

## The seed prompt (verbatim in unattended-run.sh)

> Act with full autonomy (operator directive 2026-11-10): decide and act, self-heal every defect and red gate at its owning layer, improve the tooling, runners, and plan as you go filing what you discover through add-todo, and hold the best-in-class bar against anyone; never stop at impossible without measured proof recorded in a section. Unattended RasterFold campaign. First create the session goal: "Finish RasterFold 100% complete and excellent: every open TODO section built, gated, reviewed through the pinned three-pass schedule, stamped, and committed straight on main; then the terminal release acceptance passes and the plan closes. Best lossless RGB codec in its class on the research corpus, with no placeholders." Then load the process-plan skill and run it end to end: audit, start the campaign guard and the in-session heartbeat (muse.cron_create, 3-59/5 * * * *, canonical prompt from the skill), and ship section after section through process-todo-section plus review-todo-section until query ready prints 0 runnable now. Never ask the operator a question: where a section leaves a choice open, take the industry-standard option, record the decision and its reversal cost in the section, and carry on. Work lead-only: no worker subagents are defined or delegated to (the tier roster was removed by operator directive 2026-11-10 after measured quality evidence: Ember failed its refusal probe 2 of 2 and Wonder first-pass work needed independent-round repairs). Do every task yourself, using scripts for deterministic work, and verify with the cheapest falsifier (script exit codes, then deterministic equivalence, then your reading). A commit is not a stop. A red gate is repaired at its owning layer, never bypassed. Milestone gates are capped (D99 T01 §8): at most 13 follow-up experiment rounds per gate; at the cap close the gate accepted-missed with the figures recorded and the target text unchanged, file its one dormant backlog revisit entry (D99 T01 §8 triggers: stronger model pinned, incidental re-measurement crossing the bar, new format version, new technique), never park a gate open waiting, then move on. Stop only at plan closeout, a recorded park where every leftover row is blocked or runnable-elsewhere, or an escalation the tree cannot fix.

## Dry-launching without starting a campaign

`UNATTENDED_PROMPT_OVERRIDE=<file>` is the one documented dry-launch entry point: when the variable is set, `scripts/unattended-run.sh` reads the seed prompt from that file instead of the campaign prompt below, so a dry launch can set the goal, list the loaded agents, and end the turn without acquiring a campaign guard. When the variable is unset the launcher uses the campaign prompt exactly as written below, byte for byte. The preflight still runs first either way, so a dry launch on a tree the preflight refuses never reaches Muse.

## Why it actually runs unattended

- `--yolo` disables approval and the sandbox for the run and trusts the workspace, so no tool call waits on a human. `--disable-request-user-input` withholds the question tool entirely: the run cannot park on a question. The AGENTS.md autonomy rule (operator directive 2026-11-10) covers the rest: decide and act, self-heal at the owning layer, improve tooling and plan as it goes, hold the best-in-class bar, and treat "impossible" as a claim needing measured proof in a section record.
- The run guard is the campaign guard plus the in-session cron heartbeat from `process-plan`: a stalled or crashed turn is resumed inside the same session with full context, and six resumptions with no tree change trip the stall breaker instead of burning tokens forever. Muse has no Stop hook; the guard file plus heartbeat carry it, exactly as the skill maps.
- Reviews never wait on the operator: `scripts/review-dispatch.py` runs the pinned reviewer (muse routes to Astra via the Codex CLI) through plan, adversarial round, completion, and reconciliations up to the 33-pass cap per section.
- Every commit passes the local hooks (staged-tree TODO validate, plan audit, drift) with no `--no-verify`, straight on `main`, one section per logical candidate range.

## Lead-only, no worker subagents

The tier roster (`rf-ember-literal`, `rf-spark-scout`, `rf-spark-hands`, `rf-wonder-hands` in the former `.agents/muse-agents.json`) was removed by operator directive 2026-11-10, after the run's measured evidence: Ember interpreted instead of escalating on 2 of 2 refusal probes, and Wonder first-pass work still needed independent-round repairs, so the tiers saved no total effort at equal shipped quality. The lead does every task itself, scripts do deterministic work, and quality still comes from the author-independent pipeline (section checkpoints, the gates, the pinned three-pass independent review, the stamp). Reversal cost: restore the roster file and the launcher `--agents` flag and re-qualify each tier on its refusal and known-answer probes before any delegation resumes.

### Where the savings come from, and what guarantees the quality

The aim is the most usage saved at the quality of a Wonder-Full-only run. That works only because shipped quality in this repo is decided by an author-independent pipeline (section checkpoints with named commands, the gates, the pinned three-pass independent review, the stamp), not by which model typed the diff. Delegation changes who produces the candidate; it never changes what the candidate must pass. The savings then come from moving production down (generation and its iterate-until-green loops are the expensive part) while keeping verification as cheap as it can be without weakening it, in a fixed order: script gates first (exit codes cost no model usage; the worker runs them, the lead reruns the named checkpoint and reads summary lines), then deterministic equivalence (diff scope against the spec's file list, regenerate-and-diff, oracle and known-answer byte identity), and model reading only for semantics no script can falsify (the lead's single full-diff read of Wonder-tier work). Three disciplines keep cheap tiers from burning the savings back: routing defaults down (the lead keeps only work no lower tier can do under a verifiable spec, and writes that spec first), one repair attempt per failure cause per tier then escalation, and permanent one-tier promotion of any work class that fails lead verification twice. Removal is separate and outranks both: a silent wrong output, an out-of-scope edit, or non-reproducing evidence removes that agent for the run at once (recorded, redone one tier up), never to be delegated to again in that run; repair and promotion govern honest failures only. Honest limit: equivalence holds for everything the pipeline can falsify, which is most of this repo; for open-ended judgment it cannot, which is why format decisions, gate verdicts, and bar changes never enter the ladder. Default reasoning efforts follow the tiers (Ember and Spark low, Wonder medium, the launcher pins the lead medium), and a campaign's run file records delegation counts by tier so savings stay visible against `muse usage` instead of assumed.

## Stopping and resuming

- Operator stop in words: `python3 scripts/campaign_guard.py end --reason operator-stop`, delete the heartbeat job, done (process-plan spells the order).
- Resume: double-click the shortcut again. Preflight refuses while a guard from a live run exists (its named session is still running). A dead run's guard does not stop the launch: the preflight prints `stale campaign guard: <session> (handover on start)` and passes that line, and the new session takes the guard over, never by deleting files, in this order: `CronList` and delete any heartbeat job still live for the dead run, create the fresh heartbeat job and mint a generation as `process-plan` spells, then `python3 scripts/campaign_guard.py acquire --session <new session> --phase <N> --run-file <run file> --cron-id <new job> --generation <generation> --handover <reason>` and read the handover back from the guard it prints. A heartbeat from the dead session dies with that session, so any job `CronList` still shows for it is stale and is deleted before the new job is created.
