## 3. Round 1: a Backward-Reference Method for Screen Content

> **Started:** 2026-11-12T15:14:01Z

**Origin:** discovered run=32b2775e0d5a 2026-11-12 -- Milestone 9 gate (`D05 T01 §9`) misses on the held-out screenshots (`4.6730` of lossless WebP); this is follow-up round 1 of at most 13 under the capped missed-milestone policy (`D99 T01 §8`), required by that gate's acceptance bar, routed by `docs/research.md` section 4.15 (`§2`).

**Needs:** ffmpeg with libjxl (benchmarks)

Hypothesis: on screen content most pixels repeat earlier ones exactly (`98.2%` to `99.3%` of each development screenshot lies inside a copy of at least 4 pixels, section 4.15), and method 1 pays for every repeated glyph edge (`92.7%` of its bytes code non-zero residuals). A coding method that writes an image as a sequence of literals, colour-cache hits and backward-reference copies pays once per run instead of once per pixel; the estimate of section 4.15 (`772,711` bytes for the ten development screenshots, against method 1's `3,383,489`) bounds what it can reach. The encoder keeps the smaller of this method and method 1, as it already chooses between method 1 and the palette methods, so no image grows. Non-goals: no change to method 1 or the palette methods; no predictor or other transform before the parse (only subtract-green on literals); no per-image parameter search; no near-lossless or approximate matching. This differs from the match model of `D01 T04 §2` (Already tried), which predicted each sample of a repeat inside method 1 and still coded every sample; here a copy is one token. Cost: a hash-chain parse at encode time on images that pass the attempt rule below, and at decode a copy loop; working memory of one hash table and chain (bounded below).

Prior art: lossless WebP (RFC 9649 section 5) codes ARGB pixels as literals, colour-cache indices and LZ77 copies with prefix-coded lengths and 2D-mapped distances, and wins `5.0498` times over method 1 on the development screenshots; DEFLATE and LZ77 define the overlapping copy; HEVC's screen content coding extensions (intra block copy) and JPEG XL's patches exploit the same repetition in 2D. The design below takes RFC 9649's parse objects (cache indexing, section 3.6.2.3; prefix codes, section 3.6.2.2; the 120-entry distance map, section 3.6.2.2.1) and replaces its static Huffman codes with the adaptive binary range coding RasterFold already uses (`src/rc.h`), so no code table is transmitted.

**The design (exactly this is prototyped, measured and, if accepted, ported; nothing below is tuned during the round):**

- Parse: raster order over whole RGB pixels, greedy, as `research/screenrep.py` defines it (candidates distance 1, distance `width`, and the most recent 64 positions whose next 4 pixels hash equal, every candidate at most `2^20 - 120` pixels back so its distance code fits the 40 prefix symbols; the longest exact match of 4 to 4096 pixels, the shorter distance on a tie; overlap allowed); otherwise a 256-entry colour cache (RFC 9649 section 3.6.2.3 indexing, every coded pixel inserted); otherwise a literal.
- Token kind: one adaptive binary decision "copy or not", then for a non-copy "cache hit or literal", each with a context of the previous token's kind (3 contexts each).
- Literal: subtract-green (`G`, `R - G`, `B - G` modulo 256), each channel an 8-level adaptive binary tree; `R - G` and `B - G` take the coded `G`'s top 2 bits as context, `G` none.
- Cache hit: the 8-bit index as an adaptive binary tree.
- Copy length: RFC 9649 section 3.6.2.2 prefix symbol (0 to 23) as an adaptive binary tree, then its extra bits, the top extra bit adaptive per symbol and the rest at probability one half.
- Copy distance: RFC 9649 section 3.6.2.2.1's 2D map (a distance equal to one of the 120 listed `(dx, dy)` neighbours codes as that entry's index plus 1, any other as distance plus 120), then the prefix symbol (0 to 39) as an adaptive binary tree with the previous copy's symbol class (short map entry or not) as context, then the extra bits as for lengths.
- Probabilities and counters: method 4's exact 16-bit split and counter update (`renc_bit16`, `docs/research.md` section 4.14), every counter starting at one half.
- Attempt rule (general, not image-specific): the encoder first chooses exactly as it does today (raw, a palette method or method 1, `src/fold.c`), then runs the parse; if copies cover at least half of the pixels it also encodes this method and keeps the smaller of the two (today's choice on a tie); otherwise it writes today's choice. So no image is ever larger than today, whichever method wins today. The rule reads only the parse it already ran.
- Bounds: the hash table has `2^16` heads and the chain is limited to 64 positions per probe; working memory is linear in the pixel count and stated in the result.

**Corrected 2026-11-12 (plan review `docs/reviews/01-compression/D01-T07-s3.md`):** four gaps closed; these definitions replace any looser wording above and are part of the frozen design.

- *One match search, shared by the prototype and the C.* The key of position `p` is the 12 bytes of pixels `p` to `p + 3`; its bucket is the top 16 bits of the 32-bit FNV-1a hash of those bytes (offset basis `2166136261`, prime `16777619`). `head[bucket]` holds the most recent position with that bucket (initially none) and `prev[q]` the position before `q` in the same bucket. At a position with at least 4 pixels left, the candidates are tested in this order: distance 1, distance `width`, then the bucket's chain from `head` through `prev`, at most 64 chain entries visited (an entry whose 4 pixels differ is visited and counted, since buckets collide), stopping early at a position more than `2^20 - 120` back. The longest match of 4 to 4096 pixels wins, the shorter distance on a tie. After a token, every position it covered is inserted in increasing order (`prev[q] = head[bucket]`, `head[bucket] = q`); positions with fewer than 4 pixels left are not inserted. `research/screenrep.py`'s exact-key chains remain an estimator only; the prototype implements this search, and a collision fixture (two different 4-pixel keys in one bucket) proves prototype and C emit the same tokens and bytes.
- *The grammar, completely.* The payload is the range-coded stream alone (no size field); a payload shorter than 5 bytes is refused before the range decoder is initialised (it reads 5 bytes). Each token is: decision `copy` with context `prev_kind` (0 literal, 1 cache hit, 2 copy; `prev_kind = 0` at the image start); if not a copy, decision `cache hit` with context `prev_kind`. A literal codes `G`, then `R - G` with the context `G >> 6`, then `B - G` with the context `G >> 6`, each an 8-level binary tree MSB first over 255 internal nodes per context. A cache hit codes the 8-bit index as such a tree; a hit on an entry never set is refused. A copy codes its length as `L - 3` (so lengths below 4 cannot be written): the RFC 9649 prefix symbol of `L - 3` as a 5-level binary tree MSB first (symbols 0 to 31; a decoded symbol above 23 is refused, `4096 - 3 = 4093` lying in symbol 23's range `3072..4096`), then its extra bits MSB first, the first adaptive with one counter per symbol and the rest at probability one half; `L` above 4096 or past the last pixel is refused. Then the distance code `v`: its prefix symbol as a 6-level binary tree MSB first with context `prev_short` (1 when the previous copy's `v` was at most 120, 0 otherwise and at the image start), symbols above 39 refused, then extra bits as for lengths with separate counters. `v <= 120` names entry `v - 1` of RFC 9649 section 3.6.2.2.1's table, `(dx, dy)`, giving distance `dy * width + dx`, raised to 1 when below 1; `v > 120` gives distance `v - 120`; a distance larger than the number of pixels already decoded is refused. The encoder writes, for a copy at distance `D`, `v` = 1 plus the index of the first table entry (in table order) whose distance equals `D`, and `v = D + 120` when none does (on an image narrower than 9 pixels several entries can give one distance; the first is used). The table is copied into the spec from RFC 9649 section 3.6.2.2.1 (Figure 20), read 2026-11-12. After the last pixel the decoder's input position must equal the payload size, as for method 4; anything else is refused. Every refusal is tested on a file with valid checksums, in C and in the oracle.

## 4. Round 2: Spatial Copy-Distance Inheritance, 2D Offsets, and Recency Colour Coding

> **Started:** 2026-11-13T04:43:15Z

Hypothesis: on `screens` (`§3`), method 5 spends `430,639` of its `707,897` payload bytes (`60.8%`) on copies and `211,585` bytes (`29.9%`) on 24-bit literals, for three structural reasons visible on the development screenshots alone. First, multi-row glyphs, icons, borders and code blocks translate rigidly across scanlines: when row `y - 1` copied from offset `D = dy * width + dx`, row `y` at the same or adjacent column (`p - width`, `p - width +- 1`, `p - width +- 2`, or `p - 1`) frequently continues that exact 1D distance `D`, including 2- and 3-pixel vertical glyph stems that a 4-pixel hash threshold cannot emit, whereas a global repeat queue alone is evicted across a 1280-pixel scanline. Second, non-inherited copies code `D + 120` as a flat 1D distance whenever `(dx, dy)` falls outside RFC 9649's 7-row 2D map (`110,952` of `172,665` copies in `§2` lie beyond row 1), paying log2(`dy * width`) extra bits even when `dx == 0` (vertical margins, table rules, aligned text columns) or when `dy` repeats a recent text-line baseline spacing (`rep_dy`). Third, screenshots carry `1,946` to `4,507` distinct colours (`§2`), so method 5's 256-entry direct-mapped cache suffers heavy hash collisions and evicts active anti-aliased glyph colours into 24-bit literals, while isolated 1-pixel horizontal/vertical runs pay a full cache index or literal instead of a 1-bit neighbour-equality flag. Coding (1) causal spatial + recent copy-distance inheritance (`L >= 2`) from a `(width + 3)`-entry distance ring buffer plus 4-entry `rep`, (2) decomposed 2D `(dy, dx)` offsets with a 4-entry `rep_dy` queue and `dx == 0` flag on new copies (`L >= 4`), and (3) `eq_w` / `eq_n` 1-pixel neighbour flags, a 16-entry move-to-front colour list, a 2048-entry (`11`-bit) direct colour cache, and `W_g >> 5` conditioning on literal green cuts both copy-offset bits and collision-induced literals in a single pass. Cost: one `(width + 3)`-entry `uint32_t` causal distance ring (`~5 KB` on `1280x960`), `13.3 KB` of counters (`6,655` 16-bit entries), and an `8 KB` colour cache, keeping decode working memory within `+1%` of method 5 (`-51%` below method 1). Non-goals: no change to method 1, the palette methods, or method 5's frozen decoder; no multi-pass DP or lazy parse; no pre-parse image transform; no per-image parameter search. Difference from `docs/research.md` section 3 ("Already tried"): `D01 T06 §5` (above-copy runs), `D01 T06 §6` (neighbour-candidate colour cache) and `D01 T06 §7` (recent-colour cache) modified `<= 256`-colour palette index streams where method 3's 2D neighbour pattern already captured spatial correlation; here the input is thousands-of-colours RGB24 screen content where method 5 currently has zero spatial distance inheritance, 1D distances past 7 rows, and a 256-slot direct cache.

Prior art: HEVC Screen Content Coding (ITU-T H.265 SCC, intra block copy merge/AMVP candidates from spatial neighbours `A1`/`B1`) inherits block-copy displacement vectors from causal spatial neighbours so multi-row glyphs and UI boxes transmit their offset once on their top row; LZMA (7-Zip) and Zstandard (RFC 8878 section 3.1.1.5) maintain a small recent-offset queue (`rep[0..3]`) with short-length eligibility on `rep[0]`; JPEG XL modular patches and squeeze/palette coding separate 2D `(dy, dx)` displacements and maintain recent colours; lossless WebP (RFC 9649 section 3.6.2.3) defines the multiplicative 32-bit colour-cache hash `(0x1e35a7bd * argb) >> (32 - bits)` up to 11 bits (`2048` entries).

**The design (frozen before any held-out run; every constant fixed from prior art and `§3`, nothing tuned on `heldout`):**

- *Payload and pixel 0.* Payload is the 16-bit range-coded stream alone (`renc_bit16` / `rdec_bit16` and `sc_rate[0..60]` from `§3`, every counter starting at `32768`); a payload shorter than 5 bytes is refused before range-decoder initialisation, and after pixel `n - 1` (`n = width * height`) `dec.pos` must equal `payload_size` (else refused). Pixel `p = 0` has no causal neighbours, no cache entries and no earlier positions, so it is coded unconditionally as a literal (`G` in `lit_g[4]`, `(R - G) & 255` in `lit_rg[G >> 6]`, `(B - G) & 255` in `lit_bg[G >> 6]`, each an 8-level MSB-first binary tree), sets `orig[0] = 0`, inserts position `0` into the hash chain if `n >= 4`, updates the colour state, and initializes `prev_kind = 5` (`LIT`), `prev_same_row = 0`.
- *State across pixels `p = 1 .. n - 1`.*
  - Causal copy-origin ring `orig_ring` of `ring_cap = width + 3` `uint32_t` entries (`orig[q]` stored at `orig_ring[q % ring_cap]`): every pixel `q` covered by a copy of distance `D` sets `orig[q] = D`, and every non-copy pixel `p` sets `orig[p] = 0`.
  - Recent 1D distance queue `rep[0..3]`, initialized to `[1, width, width + 1, width - 1]` (unsigned 32-bit; `width - 1` is `0` when `width == 1` and ignored by candidate filtering). On every copy of distance `D`, if `D` is in `rep`, remove it and insert `D` at index `0`; else insert `D` at index `0` and drop `rep[3]`.
  - Recent vertical-row-delta queue `rep_dy[0..3]`, initialized to `[1, 2, 4, 8]`. On every non-inherited multi-row copy (`same_row == 0`) with row delta `dy >= 1`, update `rep_dy` with `dy` by the same move-to-front rule.
  - Colour state, updated on every pixel `q` in raster order (including every pixel inside a copy): a move-to-front list `mtf` of up to 16 distinct 24-bit RGB values (`(R << 16) | (G << 8) | B`, initially empty; pixel `0` populates `mtf[0]`, so `1 <= mtf_count <= 16` for all `p >= 1`), plus a 2048-entry (`CACHE_BITS = 11`) direct colour cache indexed by `((0x1e35a7bd * (0xff000000 | rgb)) & 0xffffffff) >> 21` (initially unset).
- *Causal inherited-distance candidate list `cands` at `p >= 1`.* Let `maxd = min(p, 2^20 - 1)` (`WINDOW = 1,048,575`), `x = p % width`, `y = p // width`. Append distinct distances `d` satisfying `1 <= d <= maxd`, stopping once 4 candidates are collected, in this exact order: if `y >= 1`, `orig[p - width]`, `orig[p - width + 1]` (when `x + 1 < width`), `orig[p - width - 1]` (when `x >= 1`), `orig[p - width + 2]` (when `x + 2 < width`), `orig[p - width - 2]` (when `x >= 2`); if `x >= 1`, `orig[p - 1]`; `rep[0]`, `rep[1]`, `rep[2]`, `rep[3]`; then fallback constants `1`, `width`, `width + 1`, `width - 1`. Because `1 <= maxd` for all `p >= 1`, `cands` always has `1 <= k <= 4` distinct valid distances.
- *Deterministic single-pass parse at `p >= 1`.* Let `limit = min(4096, n - p)`.
  1. Inherited match: if `limit >= 2`, test `cands[0 .. k - 1]` in order and keep the longest exact pixel match `best_inh_len` in `2..limit` (lowest candidate index `idx` on a tie).
  2. General hash-chain match: if `limit >= 4`, test distance `1`, distance `width` (when `p >= width` and `width <= WINDOW`), and up to 64 entries of `§3`'s 16-bit FNV-1a 4-pixel bucket chain within `WINDOW`, keeping the longest exact match `best_gen_len` in `4..limit` (shorter 1D distance `best_gen_dist` on a tie). Every covered position `q` with `q + 4 <= n` is inserted into its FNV-1a bucket chain in increasing order, exactly as in `§3`.
  3. Arbitration: if `best_inh_len >= 2` and (`best_gen_len < 4` or `best_inh_len + 1 >= best_gen_len`), emit an inherited copy `(best_inh_len, idx)`. Otherwise, if `best_gen_len >= 4`, emit an inherited copy `(best_gen_len, cands.index(best_gen_dist))` when `best_gen_dist` is in `cands`, else emit a non-inherited copy `(best_gen_len, best_gen_dist)`. Otherwise emit a single-pixel token: if `x >= 1` and `rgb == pixels[p - 1]`, emit `EQ_W` (kind `1`); else if `y >= 1`, (`x == 0` or `pixels[p - width] != pixels[p - 1]`), and `rgb == pixels[p - width]`, emit `EQ_N` (kind `2`); else if `rgb` is in `mtf`, emit `MTF` (kind `3`); else if `cache[cidx] == rgb`, emit `CACHE` (kind `4`); else emit `LIT` (kind `5`). Copies have kind `0` (`COPY`).
- *Token and parameter grammar at `p >= 1`.* Prefix coding `prefix_code(val)` for `val >= 1` extends RFC 9649 section 3.6.2.2 uniformly (`val <= 4 -> sym = val - 1, nbits = 0`; `val >= 5 -> nbits = floor(log2(val - 1)) - 1, sym = 2 * nbits + 2 + (((val - 1) >> nbits) & 1), extra = (val - 1) & ((1 << nbits) - 1)`), with the top extra bit adaptive per symbol and remaining extra bits coded at `32768`:
  - `is_copy[prev_kind]` (`6` counters): `1` for a copy, `0` for a single pixel.
  - On `is_copy == 1`: code `is_inherit[prev_kind]` (`6` counters).
    - If `is_inherit == 1`: select `idx` in `0 .. k - 1` (`k = len(cands)`): `0` bits when `k == 1`; else `inh_b0[prev_kind]` (`1` -> `idx = 0`); if `0` and `k == 2` -> `idx = 1`; else if `0` and `k >= 3`, `inh_b1` (`1` -> `idx = 1`); if `0` and `k == 3` -> `idx = 2`; else `inh_b2` (`1` -> `idx = 2`, `0` -> `idx = 3`). Distance is `D = cands[idx]`. Code `L - 1` (`L >= 2`, so `val = L - 1 >= 1`) via 5-level `len_tree[1]` (symbols `0..23`, `> 23` refused) + `len_extra[1][sym]`; `L > 4096` or `p + L > n` is refused.
    - If `is_inherit == 0`: code `L - 3` (`L >= 4`, so `val = L - 3 >= 1`) via 5-level `len_tree[0]` (symbols `0..23`, `> 23` refused) + `len_extra[0][sym]`; `L > 4096` or `p + L > n` is refused. Let `py = p // width`, `px_col = p % width`. If `py == 0`, `same_row = 1` implicitly; else if `px_col == 0`, `same_row = 0` implicitly; else code `same_row = is_same_row[prev_same_row]` (`2` counters).
      - When `same_row == 1`: code `dx = D` (`1 <= dx <= min(px_col, WINDOW)`) via 6-level `dx0_tree` (symbols `0..39`, `> 39` refused) + `dx0_extra[sym]`; `dx > px_col` or `dx > WINDOW` is refused; set `prev_same_row = 1`.
      - When `same_row == 0`: code `in_rdy = is_rep_dy` (`1` counter). If `1`, select `ridx` in `0..3` via `rep_dy_b0` (`1` -> `0`), `rep_dy_b1[0]` (`1` -> `1`), `rep_dy_b1[1]` (`1` -> `2`, `0` -> `3`) and set `dy = rep_dy[ridx]`; else code `dy` via 6-level `dy_tree` (symbols `0..39`, `> 39` refused) + `dy_extra[sym]`. If `dy > py` or `dy > WINDOW`, refuse. Update `rep_dy` with `dy`. Next code `dx_zero[in_rdy]` (`2` counters): if `1`, `dx = 0`; else code `neg = dx_sign` (`1` counter, `1` for `dx < 0`, `0` for `dx > 0`) and `adx = |dx|` via 6-level `dx_tree` (symbols `0..49`, `> 49` refused) + `dx_extra[sym]`, setting `dx = -adx` if `neg` else `adx`. Check `qx = px_col - dx`: if `qx < 0` or `qx >= width`, refuse. Set `D = dy * width + dx`: if `D > WINDOW`, refuse (`1 <= dy <= py` and `0 <= qx < width` already guarantee `1 <= D <= p`). Set `prev_same_row = 0`.
  - On `is_copy == 0`: let `has_w = (x >= 1)`, `has_n = (y >= 1)`.
    - If `has_w`: let `wn_eq = 1` when `has_n` and `pixels[p - 1] == pixels[p - width]` else `0`; code `is_eq_w[prev_kind * 2 + wn_eq]` (`12` counters). If `1`, `rgb = pixels[p - 1]`, done (`prev_kind = 1`).
    - If `has_n` and (`not has_w` or `pixels[p - width] != pixels[p - 1]`): code `is_eq_n[prev_kind]` (`6` counters). If `1`, `rgb = pixels[p - width]`, done (`prev_kind = 2`).
    - Code `is_mtf[prev_kind]` (`6` counters): if `1`, decode 4-level `mtf_tree` -> `midx` (`0..15`; `midx >= mtf_count` refused), `rgb = mtf[midx]`, `prev_kind = 3`.
    - Else code `is_cache[prev_kind]` (`6` counters): if `1`, decode 11-level `cache_tree` -> `cidx` (`0..2047`; unset slot refused), `rgb = cache[cidx]`, `prev_kind = 4`.
    - Else decode literal: `wg_ctx = (G(pixels[p - 1]) >> 5)` (`0..7`) when `has_w` else `4`; `G` in `lit_g[wg_ctx]` (`8 * 255` nodes), `R = (lit_rg[G >> 6] + G) & 255`, `B = (lit_bg[G >> 6] + G) & 255`, `prev_kind = 5`.
- *Attempt rule and zero-false-negative prefilter.* `src/fold.c` first chooses among raw, method 4 and method 1, then tries method 6 (`RF_METHOD_SC2 = 6u`): method 6 is kept if and only if copies of length at least 4 (`L >= 4`, inherited or non-inherited) in the method 6 parse cover at least half of all pixels (`2 * covered4 >= n`, so `n >= 4` is required to select method 6 automatically while `rf_sc2_encode` / the oracle can still encode smaller fixtures directly for decoder coverage) and its payload is strictly smaller than the previous winner's (`payload_size < best_payload`). Because every `L >= 4` copy is still covered by duplicate 12-byte 4-pixel keys, `§3`'s `sc_likely_half` prefilter retains zero false negatives unchanged.
- *Consumers and timing-failure rollback.* `inspect` reports `"sc"` for both `RF_METHOD_SC` (`5`) and `RF_METHOD_SC2` (`6`) in text and JSON with no palette or stream fields, while `rf_info.method` in `include/rasterfold.h` documents `5` (screen content) and `6` (screen content v2). Valid and malformed method 6 files (and legacy `KAT_SC5` method 5 files) are tested on both the packed-RGB C API path and the strided bottom-up BMP CLI path.
